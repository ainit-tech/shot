# Glossary

This glossary is the project's shared language. Docs, diagrams, the UI and code use the same words with the same meanings. If a term you need is missing, add it here first and only then use it.

Throughout the documentation, terms from this glossary are underlined with dots, and hovering over one shows what it means.

## Rules

1. **One term, one meaning.** No synonyms: once a word is chosen for a concept, we don't call it by another word.
2. **A term is written the same way everywhere**: in docs, on diagrams and in the UI. Code uses the code name from the card.
3. **Don't borrow taken words.** If a well-known program already uses a word for something else, we don't use it.
4. **Every term has a kind**: tool, part of the interface, entity and so on. That way a tool is never confused with the toolbar that holds it.
5. **Terms change everywhere at once.** A new term starts as "proposed". An accepted term is renamed only together with all docs, diagrams and code.
6. **Translations use the term base.** The Russian and Hindi versions use only the equivalents listed in the [term base](#term-base).

## Statuses

- **Accepted** — the term is approved.
- **Proposed** — the term is in use but not approved yet.
- **Open** — there is a problem or several options; a decision is needed.
