# Rust и Windows API

Программа пишется на Rust, обращается к Windows API напрямую и представляет собой один небольшой исполняемый файл, который ждёт горячую клавишу в фоне.

## Вопрос

На чём писать программу, чтобы экран замирал сразу после горячей клавиши, а сама она оставалась маленькой?

## Варианты

| Вариант | За | Против |
|---|---|---|
| Rust и Windows API | Один небольшой файл без среды выполнения; быстро запускается и рисует; движок этой документации тоже на Rust | Выделение, панель и рисование делаются вручную: кода больше, чем с готовым фреймворком интерфейса |
| C# и .NET (WinForms или WPF) | Обычный выбор для таких программ: ShareX и Greenshot написаны на C#; интерфейс делается быстро | Нужна среда .NET или самодостаточная сборка на десятки мегабайт |
| Electron или Tauri | Интерфейс на HTML и CSS | Браузерный движок тяжёл (Electron) или неудобен для замороженного экрана во весь экран с рисованием; горячей клавише и захвату всё равно нужен нативный код |
| AutoHotkey | Горячие клавиши в несколько строк | Не годится для редактора с рисованием и отменой |

## Почему

Программа всё время живёт в фоне и должна откликаться сразу, поэтому ей лучше всего подходит небольшой нативный файл без среды выполнения. Rust это даёт, и в этом репозитории он уже используется. Лишней работы над интерфейсом немного: одно окно во весь экран с выделением, панелью и несколькими инструментами.

## Последствия

- Один процесс в фоне, который запускается вместе с Windows, если так сказано в настройках; его значок в области уведомлений делает скриншот, открывает настройки и закрывает программу.
- Экран снимается со всех мониторов с их масштабом, а окно во весь экран накрывает их все.
