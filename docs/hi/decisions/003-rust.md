# Rust और Windows API

प्रोग्राम Rust में लिखा जाता है, Windows API को सीधे कॉल करता है और एक छोटी एक्ज़ीक्यूटेबल फ़ाइल है, जो पृष्ठभूमि में हॉटकी का इंतज़ार करती है।

## प्रश्न

प्रोग्राम किसमें लिखा जाए, ताकि हॉटकी के तुरंत बाद स्क्रीन फ़्रीज़ हो जाए और प्रोग्राम छोटा रहे?

## विकल्प

| विकल्प | पक्ष में | विपक्ष में |
|---|---|---|
| Rust और Windows API | रनटाइम के बिना एक छोटी फ़ाइल; जल्दी शुरू होती है और तेज़ी से ड्रॉ करती है; इस रिपॉज़िटरी का दस्तावेज़ इंजन भी Rust में है | चयनित क्षेत्र, टूलबार और ड्रॉइंग हाथ से बनाने होते हैं: तैयार इंटरफ़ेस फ़्रेमवर्क की तुलना में ज़्यादा कोड |
| C# और .NET (WinForms या WPF) | ऐसे प्रोग्रामों के लिए आम पसंद: ShareX और Greenshot C# में लिखे गए हैं; इंटरफ़ेस जल्दी बनता है | .NET रनटाइम चाहिए, या दसियों मेगाबाइट का सेल्फ़-कंटेन्ड बिल्ड |
| Electron या Tauri | HTML और CSS में इंटरफ़ेस | पूरी स्क्रीन पर फ़्रीज़ की गई स्क्रीन और ड्रॉइंग के लिए ब्राउज़र इंजन भारी (Electron) या असुविधाजनक है; हॉटकी और कैप्चर के लिए फिर भी नेटिव कोड चाहिए |
| AutoHotkey | कुछ पंक्तियों में हॉटकी | ड्रॉइंग और पूर्ववत वाले एडिटर के लिए उपयुक्त नहीं |

## क्यों

प्रोग्राम हर समय पृष्ठभूमि में रहता है और उसे तुरंत प्रतिक्रिया देनी होती है, इसलिए रनटाइम के बिना छोटी नेटिव फ़ाइल उसके लिए सबसे उपयुक्त है। Rust यह देता है, और यह रिपॉज़िटरी उसे पहले से इस्तेमाल करती है। इंटरफ़ेस पर अतिरिक्त काम सीमित है: पूरी स्क्रीन की एक विंडो, जिसमें चयनित क्षेत्र, टूलबार और कुछ टूल हैं।

## परिणाम

- पृष्ठभूमि में एक प्रोसेस, जो सेटिंग्स में कहे जाने पर Windows के साथ शुरू होता है; सूचना क्षेत्र में उसका आइकन स्क्रीनशॉट लेता है, सेटिंग्स खोलता है और प्रोग्राम बंद करता है।
- स्क्रीन सभी मॉनिटरों से उनके स्केल के साथ कैप्चर होती है, और पूरी स्क्रीन की विंडो उन सबको ढक लेती है।
